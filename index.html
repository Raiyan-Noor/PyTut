Brand New Topic

What Is HTML?

Aariz - completely new territory today. Everything you've built so far has been Python: logic, functions, data. HTML is a genuinely different kind of thing, and it's worth slowing down for.

HTML stands for HyperText Markup Language. It's the language every single website on the internet is built with underneath - Google, YouTube, Discord, and every assignment page Raiyan has ever sent you.

Try this right now

Open any past assignment page you've used before. Right-click anywhere on it and choose "Inspect" (or press Ctrl+U for "View Page Source"). You'll see a wall of text wrapped in angle brackets - that's HTML. You've been looking at it this whole time without knowing it.

Don't worry if none of it makes sense yet - by the end of today, it will.

The most important distinction

Two different jobs

PythonTells the computer what to DO - logic, decisions, calculations, loops
HTMLTells the browser what to SHOW - structure and content, no logic at all

There's no if/else in HTML. No loops. No variables that change. Just labelled content - "this is a heading," "this is a paragraph," "this is a list." That's genuinely the whole idea, and it's simpler than Python in that specific way, even though the syntax will feel new.

The Bigger Picture

What Is a Markup Language?

HTML belongs to a whole category of languages called markup languages. Worth knowing the category, not just the one example.

A markup language is a system for labelling text with tags or symbols that describe its structure or meaning - not a system for giving instructions or doing logic. That's the same Python-vs-HTML distinction from a second ago, just given a proper name.

HTML isn't the only one. A few others you might actually recognise:

📝
Markdown
Lightweight and simple. You've already used this - Discord uses it! Type **bold** and it shows up bold, *italic* shows up italic.
📄
XML
Looks a lot like HTML - angle brackets and tags - but it's designed to store and move data around, not to display a page.
∑
LaTeX
Used by scientists and mathematicians to typeset papers with complicated equations and formulas.
🌐
HTML
The one you're learning today - the markup language built specifically for web pages.
Markdown example
# This is a heading I am **bold** and I am *italic*
XML example
<person> <name>Aariz</name> <age>10</age> </person>
Notice XML looks almost exactly like HTML - tags, opening and closing, nesting. Same family, different job: HTML describes a page for a human to look at, XML describes data for programs to pass to each other.
Hands On

Your First HTML Page

Open a plain text editor - Notepad, or VS Code if you have it. Save a new file called index.html. Type this exactly, then save it.

index.html
<!DOCTYPE html> <html> <head> <title>My First Page</title> </head> <body> <h1>Hello, I'm Aariz</h1> <p>This is my first ever webpage.</p> </body> </html>

What each part means

<!DOCTYPE html>Tells the browser "this is a modern HTML page" - always the first line
<html>Wraps the entire page - everything else lives inside it
<head>Information about the page - like the browser tab title - not shown on the page itself
<body>Everything that actually displays on the page
Notice every tag has an opening and closing version - <h1> and </h1>. The slash means "this is where it ends." Every tag that opens must close - this is the single most important rule in HTML.

Now open it

Find the file you just saved and double-click it. It should open in your browser and actually render as a page - a big heading and a sentence underneath.

That moment - plain text becoming a real rendered page - is the whole reveal. You just built something that a browser understands.
Building Your Vocabulary

Headings & Text Formatting

A handful of tags cover almost everything you'll ever need for plain content. Add these to your page one at a time, saving and refreshing the browser after each to see what changes.

Heading levels

try this
<h1>Biggest heading</h1> <h2>A bit smaller</h2> <h3>Smaller still</h3>

Headings go from h1 (biggest) down to h6 (smallest) - the number gets bigger as the text gets smaller, which trips a lot of people up at first.

Bold and italic

try this
<p>I play <strong>piano</strong> and <em>football</em>.</p>

<strong> makes text bold. <em> makes it italic - short for "emphasis."

Try swapping the order, nesting strong inside em, or making a whole heading bold. There's no way to break this by experimenting - refresh and see what happens.
Building Your Vocabulary

Links & Images

Two more essential tags - and your first look at something new called an attribute.

a link
<a href="https://google.com">Click here</a>
an image
<img src="photo.jpg" alt="A photo of me">

Attributes — extra info inside a tag

hrefTells a link where to go when clicked
srcTells an image which file to show
altBackup text shown if the image fails to load

Attributes always live inside the opening tag, written as name="value". You'll see a lot more of these today.

<img> has no closing tag - it's self-contained since there's no content to wrap around, just the tag with its attributes. Almost everything else needs a matching close tag, so this one's worth remembering as the exception.
Containers & Labels

div, span, and Naming Things

Two more tags, and they work a bit differently from everything else - they don't mean anything specific on their own. They're just containers, boxes for grouping content together.

a div example
<div> <h2>About Me</h2> <p>I'm 10 years old and I love coding.</p> </div>

<div> groups a whole block of content together as one unit, even though it doesn't add anything visible by itself. <span> does the same job, but for a small bit of text inside a line instead of a whole block.

If div and span don't change how anything looks, what's the point of them?

Fair question, and the honest answer: on their own, not much. They exist so you can label and group content for later - CSS will use these groupings to decide how things look, and JavaScript will use them to decide how things behave. Today you're just building the boxes; styling them is a future lesson.

id and class — naming your boxes

using id and class
<div id="about-section"> <p class="highlight">Important note</p> </div>

id vs class

id="..."A unique name for exactly one element on the page - no two elements share an id
class="..."A label you can put on many different elements - used for grouping similar things
Go back to that page you inspected earlier. Look for class="card" or class="tip" scattered everywhere - that's exactly this. Every one of your assignment pages is full of it.
New Skill

Lists & Tables

Two more tag families - one for simple lists of items, one for arranging data into rows and columns.

Lists

an unordered list
<ul> <li>Piano</li> <li>Football</li> <li>Basketball</li> </ul>

ul stands for unordered list - gives you bullet points. Swap it for ol (ordered list) and you get numbers instead - try both and compare.

More here if you want it: w3schools.com/html/html_lists.asp

Tables

A table arranges data into rows and columns - perfect for anything with multiple items that each share the same details. Three tags: table, tr (table row), and two kinds of cell - th (header cell) and td (data cell).

my_schedule.html
<table> <tr> <th>Activity</th> <th>Day</th> </tr> <tr> <td>Piano</td> <td>Monday</td> </tr> <tr> <td>Football</td> <td>Wednesday</td> </tr> </table>

The three table tags

tableThe whole table - everything else lives inside it
trOne row - the first row is usually your column headers
th / tdth = header cell (bold, for labels), td = normal data cell
Every row needs the same number of cells for the table to line up properly - if your header row has 2 th tags, every other row needs 2 td tags to match.

Making It Look Good — CSS

Remember the HTML lesson, when your pages looked completely plain and I told you "that's a different lesson"? This is that lesson. Today: CSS to style things, then JavaScript to make things actually do something.

CSS stands for Cascading Style Sheets. HTML says what something IS - a heading, a table. CSS says what it LOOKS like - what color, how big, how much space around it.

Three ways to add CSS

1. inline — directly on one tag
<p style="color: red;">This text is red</p>
2. internal — a style block in the head (what you'll mostly use today)
<head> <style> p { color: red; } </style> </head>

There's a third way - a separate .css file linked in - but that's for bigger projects. Internal is perfect for now.

CSS Deep Dive

Selectors, Properly

A selector is just the part of your CSS that answers "which elements does this rule apply to?" You've seen the three basics - now let's actually cover the full toolkit.

1. Element selector

targets every element of that type
p { color: blue; }

Every <p> on the page turns blue. Simple, but blunt - it can't target just one paragraph, only "all paragraphs everywhere."

2. Class selector

targets every element with this class
.highlight { background-color: yellow; }

The dot means "class." Any tag with class="highlight" gets styled - could be a p, a div, a li, anything. This is the selector you'll use most: reusable, flexible, not tied to one tag type.

3. ID selector

targets exactly one element
#page-title { font-size: 40px; }

The hash means "id." Since an id can only appear once per page, this always targets exactly one thing.

4. Grouping selectors — style several things at once

comma-separated
h1, h2, h3 { font-family: Arial; color: darkblue; }

Same rule, three different selectors, separated by commas. Saves you writing the same block three times.

5. Descendant selector — targeting something inside something else

a space means "inside"
table td { text-align: center; }

This means "any <td> that's inside a <table>" - not every td on the whole page, just ones nested inside a table. A space between two selectors always means "descendant of."

Bonus: pseudo-classes

:hover — style on mouseover
button:hover { background-color: lightgreen; }

This only applies while the mouse is actually hovering over the button - a small taste of CSS reacting to something happening, without needing any JavaScript at all.

Which one do I use?

elementBroad, page-wide defaults - e.g. all paragraphs use this font
classYour main tool - reusable styling for a group of things
idOne unique element - used sparingly, more often for JavaScript than styling
CSS Deep Dive

Good Practices

CSS is easy to write badly and still have it "work" - the page looks fine, but the code underneath turns into a mess nobody can maintain, including future-you. A few habits worth building from day one.

1. Prefer classes over ids for styling

An id can only be used once, so styling with ids means rewriting the same rule over and over for every similar element. Save id for when you genuinely need to target one unique thing - often that's JavaScript's job (getElementById), not CSS's.

2. Avoid inline styles

style="color: red;" directly on a tag works, but it's mixed in with your content, can't be reused anywhere else, and is genuinely painful to find and update later. Keep styling in your <style> block (or a separate CSS file), and structure in your HTML. Two different jobs, two different places.

3. Name classes by purpose, not appearance

weaker
.yellow-box { background: yellow; }
stronger
.warning-box { background: yellow; }

If you later decide warnings should be orange instead of yellow, .warning-box still makes sense. .yellow-box would suddenly be a lie.

4. Keep selectors as simple as they can be

overly specific — hard to read, hard to override
div#content table tbody tr td.highlight { }
simple — clear, reusable
.highlight { }

The shorter version does the same job and is far easier to reuse anywhere else you need that style.

One more small habit: use lowercase-with-hyphens for class names - event-table, not EventTable or eventTable. It's the standard convention, and consistency matters more than which style you pick.

The Big One

What Is JavaScript?

Here's the missing piece. HTML describes structure. CSS describes appearance. Neither one can make a decision, do maths, or react to a click. JavaScript is different - it's a real programming language, running right inside the browser.

JavaScript (JS) is the language that makes web pages actually DO things - respond to clicks, update content, check conditions, run loops. It's the browser's equivalent of Python.

The three-layer picture

HTMLStructure - what's on the page
CSSStyle - what it looks like
JavaScriptBehavior - what happens when things change or get clicked

Here's the good news: you already know how to think like a programmer. You know what a variable is, what a function does, how a loop works, how an if statement makes a decision. JavaScript isn't a new way of thinking - it's the same ideas from Python, wearing different clothes. Today's whole plan is to walk through everything you already know and see its JS outfit.

where JS lives in a page
<body> <h1>My Page</h1> <script> console.log("Hello from JavaScript"); </script> </body>

console.log() is JavaScript's version of print() - it doesn't show on the page, it shows in the browser's developer console (the same Inspect panel you used in the HTML lesson - there's a "Console" tab in there).

Python, But Make It JS

Variables

Let's go one Python concept at a time. First up - variables.

🐍
Python
name = "Aariz"
age = 10
⚡
JavaScript
let name = "Aariz";
let age = 10;

What's different

letJS needs a keyword before a new variable - let (or const, for a value that never changes)
;Lines usually end with a semicolon in JS - Python never uses these
naming rulesSame as Python - letters, numbers, underscores, can't start with a number, no spaces

Use const when a value should never change, let when it might. Try both in a script tag and print them with console.log.

try this
let score = 5; score = score + 1; console.log(score); // 6 const birthYear = 2016; // birthYear = 2017; this would cause an error - const can't change
Python, But Make It JS

Conditionals

🐍
Python
if score >= 20: print("Great!") elif score >= 10: print("Good") else: print("Try again")
⚡
JavaScript
if (score >= 20) { console.log("Great!"); } else if (score >= 10) { console.log("Good"); } else { console.log("Try again"); }

What's different

( )The condition needs parentheses around it
{ }Curly braces replace Python's colon + indentation to mark what's inside
else ifTwo words instead of Python's single elif
===Use three equals signs to compare values - a JS quirk worth remembering
Watch out for === vs ==. Always use === (triple equals) when comparing values in JS - == exists too, but it can quietly convert types in confusing ways. === is the safe default, every time.
Python, But Make It JS

Loops

This is the one that looks the most different at first glance.

🐍
Python
for i in range(5): print(i)
⚡
JavaScript
for (let i = 0; i < 5; i++) { console.log(i); }

JS spells out the three parts Python's range() hides for you: start (let i = 0), condition to keep going (i < 5), and what happens each round (i++, meaning "add 1").

The friendlier version — for...of

Looping over a list feels much more like Python if you use for...of instead:

🐍
Python
hobbies = ["Piano", "Football"] for hobby in hobbies: print(hobby)
⚡
JavaScript
let hobbies = ["Piano", "Football"]; for (let hobby of hobbies) { console.log(hobby); }
Genuinely almost identical to Python here - just add "let" and "of", swap print for console.log. Use for...of whenever you're looping through a list of things; save the three-part for loop for when you specifically need to count.
Python, But Make It JS

Functions

This one's the closest match of all.

🐍
Python
def double(number): return number * 2 print(double(5))
⚡
JavaScript
function double(number) { return number * 2; } console.log(double(5));

What's different

functionReplaces Python's def
{ }Curly braces mark the function body instead of indentation
returnWorks exactly the same as Python - sends a value back

Parameters, return values, calling a function with different arguments - all of that is identical in spirit. Only the punctuation changed.

Python, But Make It JS

Arrays & Objects

This is the one that should feel most familiar of all - you've done a version of this dozens of times already, with your JSON work.

Lists → Arrays

🐍
Python list
hobbies = ["Piano", "Football"] print(hobbies[0])
⚡
JS array
let hobbies = ["Piano", "Football"]; console.log(hobbies[0]);

Nearly identical. Square brackets, comma-separated, indexed from 0. This barely counts as new syntax.

Dictionaries → Objects

🐍
Python dict
player = {"name": "Aariz", "sport": "football"} print(player["name"])
⚡
JS object
let player = {name: "Aariz", sport: "football"}; console.log(player.name); console.log(player["name"]);
One genuinely new thing: JS lets you use dot notation - player.name - as well as bracket notation. Python dictionaries only ever let you use brackets. Both work in JS; dot notation is more common when you already know the key name.

The moment this all connects

Remember response["choices"][0]["message"]["content"] from your API work? That entire structure - an array containing an object, containing more nested data - is exactly what JavaScript arrays and objects look like too. When you called an API in Python, the JSON you got back would look almost identical if you'd been doing it in JavaScript instead.

starter

The Real Payoff

Making JS Actually Touch the Page

Everything so far has lived in the console - useful for learning, but not visible on the actual page. Here's how JavaScript reaches out and changes what someone sees.

click a button, change the page
<button onclick="sayHello()">Click me</button> <p id="message"></p> <script> function sayHello() { document.getElementById("message").textContent = "Hello, Aariz!"; } </script>

The three pieces

onclickAn attribute on the button, naming a function to run when clicked
getElementByIdFinds the exact element with that id - remember id from the HTML lesson?
.textContentThe text inside that element - set it to change what's displayed
Every single assignment page Raiyan has ever sent you uses exactly this pattern for its Next and Back buttons. onclick="changePage(1)" - you've clicked this pattern hundreds of times. Now you know what it actually does.

You can also change style this way, not just text:

changing CSS from JS
document.body.style.backgroundColor = "lightblue";
This is genuinely the moment HTML, CSS, and JS become one thing instead of three separate lessons - JavaScript reaching out and changing what CSS controls, live, in response to something a person did.

Back to Basics — Variables

Afraz, let's slow right down and make sure variables feel completely solid. No judgment here - this stuff is genuinely easy to lose track of, and a quick refresh now makes everything after it click faster.

Think of a variable as a labelled box. You put a value inside it, and you give the box a name so you can find it again later.

the simplest possible example
score = 10 # the box is named "score", and it holds the value 10
That's it. That's a variable. Everything else today just builds on this one idea.
Quick Refresh

Declaring & Assigning

Creating a variable and putting a value in it is called assignment. The = sign does this - and it means something a little different from maths class.

assignment
goals = 3 print(goals) # prints 3

In maths, = means "these two things are equal." In Python, goals = 3 means something different: "put 3 into the box called goals." It's an instruction, not a statement of fact.

You can change what's inside

reassigning a variable
goals = 3 print(goals) # 3 goals = 5 print(goals) # 5 - the box now holds a new value
The old value doesn't stick around anywhere - once you reassign, it's just gone, replaced by the new one. Try this yourself: create a variable, print it, change it, print it again.
Quick Refresh

Naming Your Variables

A variable can be called almost anything you want. A few real rules to follow though:

The rules

letters, numbers, _Names can use letters, numbers, and underscores
can't start with a numberscore1 is fine, 1score is not
no spacesUse an underscore instead - player_name, not player name
case mattersScore and score are two completely different variables
all valid names
age = 10 player_name = "Afraz" totalGoals = 7 _secret = "shh"
all invalid names
1player = "Afraz" # can't start with a number player name = "Afraz" # no spaces allowed
Pick names that actually describe what's inside the box. score is better than x. player_name is better than p. Your future self reading the code will thank you.
Quick Refresh

Using Variables

Once a variable holds a value, you can use it just like you'd use the value itself - in maths, in print statements, anywhere.

using variables in maths
goals = 3 assists = 2 total = goals + assists print(total) # 5
a variable can even use itself
score = 10 score = score + 1 print(score) # 11

That last one trips people up at first - score = score + 1 looks like it shouldn't work. Read the right side first: "take whatever score currently is, add 1." Then the left side happens: "now put that new number back into score." Right side calculates, left side stores.

Try this yourself: make 2 variables holding numbers, add them together into a third variable, and print the result.
The Real Test

Challenge: Swap Two Variables

Here's a genuinely tricky problem that really tests whether variables make sense to you. Take your time with this one - no need to write anything down or send it anywhere, just work through it until it clicks.

1
Swap the values

You're given two variables: a = 5 and b = 10. Write code that swaps them, so afterwards a holds 10 and b holds 5.

Before: a = 5, b = 10
After: a = 10, b = 5

Try it before reading further

Your first instinct might be this:

the tempting but WRONG way
a = 5 b = 10 a = b # a is now 10 - looks right so far b = a # uh oh
Run this and check what b ends up being. It's not 5. By the time you run b = a, a has ALREADY been overwritten with b's value - so you're really just copying 10 into b too, and a's original 5 is gone forever, nowhere to be found.
You need somewhere to keep the value of "a" safe before you overwrite it. Try creating a third variable - call it temp - and store a's original value in there first, before anything else changes.
If you genuinely get why the naive version fails, and why a temp variable fixes it, variables are solid. That's the whole point of this refresh - no need to submit anything, just walk Raiyan through it whenever you're ready.
