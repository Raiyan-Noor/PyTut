The Web · Big Picture

How the Web Actually Works

Aariz - every website is built from HTML, CSS and JavaScript, but those just show a page. Today you find out where pages come from, and you build the thing that sends them: a server.

Two computers having a conversation

Every time you open a website or an app, two computers talk. That is the whole internet, really. They have two jobs:

The two roles

clientthe one that asks. Your browser, your phone app, or a tool in the terminal.
serverthe one that answers. A program sitting on a computer, waiting for questions.
requestthe question the client sends: "give me the events page".
responsethe answer the server sends back: the page, some data, or an error.

Restaurant picture

You are the client. The menu is what you are allowed to ask for. The waiter carries your order (the request) to the kitchen (the server), and brings back your food (the response). If you order something not on the menu, the waiter comes back with "sorry, we don't have that" - the web has a number for that too, which you will meet soon.

It is just a function call

You already know this pattern from Python. Compare:

Python - calling a function
result = add(2, 3) # ask, get an answer back
The web - calling a server
GET http://localhost:3000/api/events # ask, get an answer back
A request is like calling a function that lives on another computer. The path (/api/events) is the function's name, and the response is its return value.

What is localhost?

Normally the client and the server are different computers far apart. While you are building, your own computer plays both roles. The address localhost just means "this computer", and the number after it, like :3000, is the port - which door of your computer the server is listening at.

When you type google.com into a browser, which one is the client and which is the server?

Answer: your browser is the client. Google's computers are the server. The page you see is the response.
The Web · The Language

URLs, Methods and Status Codes

Clients and servers need to agree on how to talk. There are three things to learn, and they come up in every request.

1. The URL has parts

anatomy of a URL
http://localhost:3000/api/events/2?sort=name

Break it up

http://the protocol - the rules for talking
localhostthe host - which computer
:3000the port - which door
/api/events/2the path - which thing you want
?sort=namethe query - extra options (we will not need it yet)

2. The method says what you want to do

Besides the address, every request has a method - a verb. And you already know the same four ideas from Python lists:

Methods

GETread something. Like looking at my_list[2].
POSTcreate something new. Like my_list.append(x).
PUTreplace something. Like my_list[2] = x.
DELETEremove something. Like my_list.remove(x).
When you type an address into your browser and press Enter, the browser always sends a GET. That is why we need a different tool (curl) to send the other kinds.

3. The response has a status code

Every response starts with a number that says how it went:

Status codes

200OK - here is what you asked for
201Created - I made the new thing
400Bad request - you sent something wrong or missing
404Not found - that thing does not exist
500Server error - I broke (the server's fault)
The first digit tells the story: 2xx means success, 4xx means the client made a mistake, 5xx means the server made a mistake.

Check yourself

A client asks for /api/events/9999 but the server only has events 1 to 3. Which code comes back? What if the client tries to create an event but forgets to send a name?

404 for the missing event - it was not found. 400 for the missing name - the client sent a bad request.
The Web · Data

APIs and JSON

A server can send back a whole page (HTML), but apps usually want just the data, so they can show it however they like. A server that gives out data like this is called an API.

API in one sentence

An API is a menu of things a program is allowed to ask a server for, plus the format the answers come back in.

The format almost everyone uses is JSON. Here are three ways of writing the same event:

Python dictionary
event = {'name': 'Piano Recital', 'time': '5pm'}
JavaScript object
const event = { name: 'Piano Recital', time: '5pm' };
JSON - plain text sent over the web
{"name": "Piano Recital", "time": "5pm"}
JSON is stricter than the other two: keys and text values must use double quotes. Single quotes are not allowed in JSON.

JSON is only text, so any language can read it. Your Express server will be JavaScript, but a Python program could call it and understand the answer just as easily. That is why JSON became the common language between computers.

Routes: the names on the menu

Each thing the API can do is called a route: a method plus a path. This is the menu you will build in this lesson:

Events API

GET /api/eventsgive me all events
GET /api/events/2give me just event number 2
POST /api/eventscreate a new event
DELETE /api/events/2remove event number 2
Which of the routes above is closest to Python's append? Which to remove?

Answer: POST /api/events is append, DELETE /api/events/2 is remove.

JavaScript normally runs inside a web page. Node.js lets JavaScript run directly on your computer, the same way Python does. That is how we can write a server in JavaScript.

Express · Server #1

Your First Server

Create server.js in your folder and type this in. Do not copy-paste - type it, and read each line as you go.

server.js
const express = require('express'); const app = express(); const PORT = 3000; app.get('/hello', (req, res) => { res.send('Hello from my very first server!'); }); app.listen(PORT, () => { console.log('Server running at http://localhost:' + PORT); });

Line by line, in Python terms

What it means

requirelike import in Python. Brings Express into the file.
appyour server. express() creates one, like creating an object.
app.get"when someone sends a GET to this path, run this function".
(req, res)the function's two inputs: req is the request that came in, res is how you send the response out.
=>an arrow function - the same job as Python's def.
res.sendsend text back as the response.
app.listenopen the shop: start waiting for requests on port 3000.

Run it

terminal
node server.js

You should see Server running at http://localhost:3000. The terminal now stays busy - that is the server waiting. Open your browser at http://localhost:3000/hello and you will see your message.

To stop the server press Ctrl + C in its terminal. Whenever you change server.js, stop it and run node server.js again - the server does not notice edits by itself.

What if it goes wrong?

"Cannot GET /" - you visited a path with no route. We only built /hello, so add /hello to the address.

"Cannot find module 'express'" - run npm install express inside the project folder.

"EADDRINUSE" - port 3000 is already taken, usually by an older server you forgot to stop.
curl · The Command Line Client

Meet curl: A Browser Without the Browser

Your browser can only easily do GET. curl is a command-line tool that can send any request and show you the raw answer. Developers use it constantly to test servers. You are going to learn its flags.

You need two terminal windows. Terminal 1 keeps running node server.js. Terminal 2 is where you type curl commands. If you stop the server, curl has nobody to talk to.

Your first curl

terminal 2
curl http://localhost:3000/hello

It prints the same message the browser showed. Now let's see what the browser was hiding.

-i shows the response headers

terminal 2
curl -i http://localhost:3000/hello
what comes back
HTTP/1.1 200 OK X-Powered-By: Express Content-Type: text/html; charset=utf-8 Content-Length: 32 Hello from my very first server!

The first line has the status code (200 OK). The lines under it are headers - notes about the response. A blank line, then the body.

-v shows the whole conversation

terminal 2
curl -v http://localhost:3000/hello
trimmed
> GET /hello HTTP/1.1 > Host: localhost:3000 > User-Agent: curl/8.5.0 > Accept: */* > < HTTP/1.1 200 OK < Content-Type: text/html; charset=utf-8 < Content-Length: 32

Lines starting with > are what you sent (the request). Lines starting with < are what the server sent back (the response). That is the whole web conversation, in plain sight.

Flags so far

-iinclude the response headers in the output
-vverbose: show request and response, line by line
-ssilent: hide the progress meter, just print the body
Windows PowerShell: curl is secretly a different command there. Type curl.exe instead of curl everywhere in this lesson. Command Prompt, Mac and Linux are fine with plain curl.

Try it

  • Run curl on your /hello route
  • Run it again with -i and find the status code
  • Run it with -v and find the line starting with > GET
  • Visit a path that does not exist, like /nope, with -i. What status code do you get?
You get 404 Not Found. The server has no route for /nope.
Express · Server #2

An API That Serves Events

Time to make a real API. Replace your server.js with this. It gives the server some data and two GET routes. Compare the data to Python:

Python
events = [ {"id": 1, "name": "Piano Recital"}, {"id": 2, "name": "Football Match"}, ]
server.js
const express = require('express'); const app = express(); const PORT = 3000; const events = [ { id: 1, name: 'Piano Recital', date: 'Saturday', time: '5pm', location: 'Music Hall' }, { id: 2, name: 'Football Match', date: 'Sunday', time: '4pm', location: 'School Field' }, { id: 3, name: 'Birthday Party', date: 'Friday', time: '6pm', location: 'Funland' } ]; let nextId = 4; app.get('/hello', (req, res) => { res.send('Hello from my very first server!'); }); app.get('/api/events', (req, res) => { res.json(events); }); app.get('/api/events/:id', (req, res) => { const id = Number(req.params.id); const event = events.find(e => e.id === id); if (!event) { return res.status(404).json({ error: 'Event not found' }); } res.json(event); }); app.listen(PORT, () => { console.log('Server running at http://localhost:' + PORT); });

New ideas

Read these carefully

res.jsonlike res.send but converts your JS object/array to JSON text and labels it as JSON.
:ida placeholder in the path. Visit /api/events/2 and req.params.id becomes "2".
Number()paths are always text, so we convert it, like Python's int().
.findgoes through the array and returns the first item where the test is true. A Python loop with an if and a return does the same.
res.status(404)set the status code before sending. Without it, you would send 200 even for errors.
returnstops the function right there, so the success line below does not also run.
the same search in Python
def find_event(events, id): for e in events: if e["id"] == id: return e return None

Call it with curl

terminal 2
curl http://localhost:3000/api/events curl http://localhost:3000/api/events/2 curl -i http://localhost:3000/api/events/99
expected for the last one
HTTP/1.1 404 Not Found Content-Type: application/json; charset=utf-8 {"error":"Event not found"}
Remember to stop and restart the server (Ctrl + C, then node server.js) every time you change the file.
Why do we write Number(req.params.id) instead of using req.params.id directly?

Answer: the id from the path is text, like "2". The ids in the array are numbers. In JavaScript "2" === 2 is false, so find would never match anything.
Express · Server #3

POST: Sending Data To The Server

So far curl only asked for things. Now we send data to the server to create a new event. Add these two pieces to server.js.

First, right after const PORT = 3000;, add one line that teaches Express to read JSON that clients send:

server.js
app.use(express.json());

Then add this route anywhere above app.listen:

server.js
app.post('/api/events', (req, res) => { if (!req.body || !req.body.name) { return res.status(400).json({ error: 'name is required' }); } const newEvent = { id: nextId, name: req.body.name, date: req.body.date, time: req.body.time, location: req.body.location }; nextId = nextId + 1; events.push(newEvent); res.status(201).json(newEvent); });

What each part does

req.bodythe JSON data the client sent, already turned into a JS object
400 checkif the client forgot the name, refuse politely and say why
events.pushJS version of append
201"Created" - the correct code for a successful POST

The curl command for POST

Mac / Linux / Git Bash
curl -X POST -H "Content-Type: application/json" -d '{"name":"Recital","date":"Monday"}' http://localhost:3000/api/events

Flag by flag

-X POSTuse the POST method instead of GET
-Hadd a header. Here: tell the server the body is JSON
-dthe data (body) to send
Windows has trouble with the quotes. In Command Prompt, escape the inner quotes: -d "{\"name\":\"Recital\"}". The easiest fix that works everywhere: put the JSON in a file called body.json, then use -d @body.json (the @ means "read the data from this file").
body.json
{"name": "Recital", "date": "Monday"}
works on every system
curl -X POST -H "Content-Type: application/json" -d @body.json http://localhost:3000/api/events
expected response (status 201)
{"id":4,"name":"Recital","date":"Monday"}

Now run curl http://localhost:3000/api/events again. Your new event is in the list!

Experiments

  • Send a POST with -i and find the 201
  • Send a POST with no "name" in the JSON. What do you get back?
  • Send the POST without the -H header. What happens, and why?
  • Stop the server and start it again, then list the events. Where did your event go?
No name: 400 and {"error":"name is required"}.

No header: also a 400. Without Content-Type: application/json Express does not read the body, so req.body is empty and the name check fails.

After a restart: gone! The events live in a variable in memory, and memory is wiped when the program stops. This is exactly why programs save to files or databases - the same idea as the file storage lesson.

Part 2 · Front End Talks To Back End

fetch(): Show Server Data On The Page

fetch() is how JavaScript in the browser makes a request, the same thing curl did, but from code. Here is a complete page that loads your events and displays them:

inside public/index.html, before
<script> async function loadEvents() { const response = await fetch('/api/events'); const events = await response.json(); const list = document.getElementById('list'); list.innerHTML = ''; for (const e of events) { const li = document.createElement('li'); li.textContent = e.name + ' - ' + e.date; list.appendChild(li); } } loadEvents(); </script>

New ideas, in Python terms

Read carefully

fetch(url)sends a GET request, like curl url
await"wait here until the answer arrives". Like input() pausing Python until the user types.
asynca function that uses await must be marked async
response.json()turns the JSON text into a real JS array, like json.loads
createElementbuilds a new HTML tag from JS
textContentputs text inside it, safely
Security rule: when you show text that a user typed, use textContent, never innerHTML. If someone types <script>...</script> as an event name, innerHTML would actually run it. textContent just shows it as harmless text. This mistake is called XSS and it is one of the most common ways websites get hacked.

Check

  • Open the page: do you see your events from the server?
  • Add an event with curl, refresh the page, and watch it appear
  • Open DevTools (F12) → Network tab → reload. Find the events request and look at its status and response, the same things curl -i showed you
Why is loadEvents declared async?

Answer: because it uses await. Fetching takes time, and await lets the function pause until the server has replied without freezing the whole page.
Part 2 · Forms

Sending Data With A Form

Now let a person add an event from the page instead of curl. Add a form above the list:

index.html
<form id="form"> <input id="name" placeholder="Event name"> <input id="date" placeholder="Date"> <button type="submit">Add</button> </form> <p id="msg"></p> <ul id="list"></ul>

And this function in your script, with one line after it that connects it to the form:

script
async function addEvent(evt) { evt.preventDefault(); const name = document.getElementById('name').value; const date = document.getElementById('date').value; const response = await fetch('/api/events', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ name: name, date: date }) }); const msg = document.getElementById('msg'); if (!response.ok) { const problem = await response.json(); msg.textContent = 'Error: ' + problem.error; return; } msg.textContent = 'Added!'; document.getElementById('form').reset(); await loadEvents(); } document.getElementById('form').addEventListener('submit', addEvent);

Match it to your curl command

The same pieces you used before

method: 'POST'-X POST
headers-H "Content-Type: application/json"
body-d '{"name": ...}'
JSON.stringifyturns a JS object into JSON text, like json.dumps
response.oktrue for status 200 to 299, false for 400 or 404 and friends
preventDefaultstops the browser reloading the page when a form is submitted, which is its default behaviour
Notice how the page shows the server's own error message when something is wrong. Good websites always tell the person what went wrong instead of silently doing nothing.
Add an event with an empty name. What appears, and which status code did the server send?

Answer: the page shows Error: name is required, and the server sent 400. Look in the Network tab to confirm.
Part 2 · Memory That Lasts

Saving Data To A File

Right now a server restart wipes everything, because the data lives in a variable. A real website keeps its data in a file or database. Let's use a JSON file. You did this in Python before:

Python
import json with open("events.json") as f: events = json.load(f) with open("events.json", "w") as f: json.dump(events, f)
Node (add near the top of server.js)
const fs = require('fs'); const FILE = 'events.json'; function loadEvents() { if (!fs.existsSync(FILE)) { return []; } const text = fs.readFileSync(FILE, 'utf8'); return JSON.parse(text); } function saveEvents(events) { fs.writeFileSync(FILE, JSON.stringify(events, null, 2)); }

Python vs Node

json.loadJSON.parse(text)
json.dumpJSON.stringify(data)
open(...).read()fs.readFileSync(file, 'utf8')
open(..., "w")fs.writeFileSync(file, text)
os.path.existsfs.existsSync(file)

Then change your routes so they load, change, save instead of using a global array:

server.js
app.get('/api/events', (req, res) => { res.json(loadEvents()); }); app.post('/api/events', (req, res) => { if (!req.body || !req.body.name) { return res.status(400).json({ error: 'name is required' }); } const events = loadEvents(); const newEvent = { id: Date.now(), name: req.body.name, date: req.body.date }; events.push(newEvent); saveEvents(events); res.status(201).json(newEvent); });
Date.now() is the current time in milliseconds, so every new event gets its own unique id without having to count. Fine for a small project like this.

Make your life easier

Instead of stopping and restarting after every edit, start the server like this and it restarts itself whenever you save server.js:

terminal
node --watch server.js
Add an event on the page, stop the server, start it again, then refresh. Is the event still there? Open events.json in your folder and look at it.

It should survive the restart, and the file contents are exactly the JSON the API sends. That is the whole trick: the database here is just a text file.

The Assignment

Making The Front End Look Good

A website that works but looks messy is only half done. Good design is not magic. It is five habits. Follow them and your page will look professional.

1. Pick a small palette and name it

Choose one main colour, one background, one text colour, plus maybe a few accent colours. Store them as CSS variables so you can change the whole site in one place:

style.css
:root { --bg: #f4f1ff; --card: #ffffff; --ink: #1d1b2e; --brand: #5b3df5; --radius: 16px; } body { background: var(--bg); color: var(--ink); }

2. One font, a few sizes

Use a single font family and only a handful of sizes: a big title, a section heading, normal text, small text. Too many fonts or sizes looks chaotic.

style.css
body { font-family: system-ui, 'Segoe UI', sans-serif; line-height: 1.5; } h1 { font-size: 2.5rem; } h2 { font-size: 1.1rem; }

3. Space is the secret

Beginners squash everything together. Give things room: padding inside boxes, gap between them, and a maximum width so text lines do not stretch across the whole screen. Put content in cards:

style.css

Questions That Answer True or False

Afraz - so far your programs run every line, top to bottom, no matter what. Real programs decide things. To decide, a program first asks a yes/no question. In Python, a yes/no question is called a comparison, and the answer is always a bool - True or False. A bool is a value that can only be True or False.

The six comparisons

==is equal to
!=is NOT equal to
&gt;is greater than
&lt;is less than
&gt;=greater than or equal to
&lt;=less than or equal to
try these
print(5 > 3) print(10 == 10) print(4 != 4) print(7 <= 6)

Python answers:

True
True
False
False
The most common mistake in all of Python: = and == are different! One equals sign stores a value (age = 10). Two equals signs ask a question (age == 10 means "is age equal to 10?").

Variables work too

with variables
height = 130 print(height >= 120) print(height == 100)

Output: True then False

Say your answers out loud

  • 8 > 8
  • 8 >= 8
  • 3 != 4
  • 10 == 5 + 5
8 > 8 is False (8 is not bigger than itself).
8 >= 8 is True.
3 != 4 is True.
10 == 5 + 5 is True - the maths on the right happens first.
Decisions · if

Making Python Decide With if

Now we use those True/False answers to make decisions. An if says: "only run this code when the question is True."

your first if
height = 130 if height >= 120: print("You can ride the roller coaster!")

Output: You can ride the roller coaster!

Three rules you must remember

1. colonthe if line ends with a :
2. indentthe code that belongs to the if is pushed in with 4 spaces (or one Tab)
3. True onlyif the question is False, Python skips the indented lines completely

What if the answer is False?

height is too small
height = 100 if height >= 120: print("You can ride the roller coaster!") print("Have a nice day")

Output: Have a nice day

Only the last line printed. Look at print("Have a nice day") - it is not indented, so it is not part of the if. It always runs. Indentation is how Python knows which lines belong inside.

Forgetting the indent gives IndentationError. Forgetting the colon gives SyntaxError. Both are very normal. Read the error message, it tells you which line.

Check yourself

what prints?
coins = 5 if coins > 10: print("Rich!") print("Done")
Only Done. The question 5 > 10 is False, so "Rich!" is skipped.
Decisions · else

else: The Plan B

Skipping when False is fine, but often you want to do something different instead. That is what else is for. Think of a fork in a road: the question picks which way you go, and you always take exactly one of them.

if and else
height = 100 if height >= 120: print("You can ride!") else: print("Sorry, too small.")

Output: Sorry, too small.

Rules

elsehas no question of its own. It means "otherwise".
colonelse: also ends with a colon
alignelse lines up exactly under its if
indentits own code is indented too
Exactly one of the two blocks runs, never both and never neither. That makes if/else great for yes-or-no decisions.

Example: even or odd

The % sign gives the remainder after dividing. 7 % 2 is 1 because 7 is 3 groups of 2 with 1 left over. If a number divided by 2 has remainder 0, it is even.

even or odd
number = 8 if number % 2 == 0: print("even") else: print("odd")

Output: even. Change number to 7 and run it again in Thonny.

Decisions · Text

Comparing Text and Asking Questions

Comparisons work on text as well. Putting it together with input() lets your program react to the person using it.

a password check
password = "tiger" guess = input("Password? ") if guess == password: print("Welcome in!") else: print("Wrong password.")

Type tiger and you get in. Type Tiger with a capital T and you get Wrong password. Python is picky: capital and small letters count as different.

Be less picky with .lower()

.lower() makes everything small letters
print("Tiger".lower()) # tiger print("TIGER".lower()) # tiger guess = input("Password? ") if guess.lower() == "tiger": print("Welcome in!")
Read guess.lower() == "tiger" in two steps: first guess.lower() turns whatever they typed into small letters, then == "tiger" asks if it matches.

Numbers from input()

Remember: input() always gives text, even when someone types a number. To compare with a number, convert first:

age check
age = int(input("How old are you? ")) if age >= 10: print("You are 10 or older") else: print("You are under 10")
If you forget int(), Python tries to compare text with a number and shows a TypeError. The fix: wrap the input in int().

Question

What does this print if the person types BOB?

predict
name = input("Name? ") if name.lower() == "bob": print("Hi Bob!") else: print("Who are you?")
Hi Bob! - "BOB".lower() becomes "bob", which equals "bob".
